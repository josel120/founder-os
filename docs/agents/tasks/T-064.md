# T-064: Sign-in always calls the page's own origin

- Status: done
- Owner: claude
- Size: S
- Depends on: T-062

## Goal
On the deployed app, every sign-in failed with "Unable to connect". The browser auth client used `NEXT_PUBLIC_BETTER_AUTH_URL` when it was set. The owner had set it during the earlier manual setup, and it pointed at another address than the one being browsed. The CSP (`connect-src 'self'`) then blocks the request. The client now always calls the page's own origin, because the auth API is always on the same deployment.

## Acceptance criteria
- [x] `src/lib/auth-client.ts` uses `window.location.origin` in the browser and ignores `NEXT_PUBLIC_BETTER_AUTH_URL`; unit test with stale values (another host, localhost).
- [x] RUNBOOK and `.env.example` no longer tell anyone to set it.
- [x] lint, typecheck, 423 unit tests, build, full E2E 37/37.
