# T-059: Prune stale rate-limit rows so client IPs are not kept indefinitely

- Status: review
- Owner: claude
- Size: S
- Depends on: T-053

## Goal
The `rate_limit` table (T-053) keys rows on `ip|path`, the first stored personal data that is not the owner's own. Rows for an IP that stops sending requests are never removed, because Better Auth only resets a row when that key returns. Stale rows are deleted so an IP is not kept longer than a day.

## Acceptance criteria
- [x] Rows whose `last_request` is older than a documented retention (proposed 24 h) are deleted by an owner-free mechanism that works on Vercel serverless: for example an opportunistic `DELETE … WHERE last_request < $cutoff` at most once per window from the auth handler, or a Vercel Cron route protected by `CRON_SECRET`. Pick one and record why in ADR-016.
- [x] The delete never touches rows inside the active window, so limits still hold (unit test at the boundary).
- [x] `docs/RUNBOOK.md` states the retention and how to check it (`SELECT count(*), min(last_request) FROM rate_limit`).
- [ ] If a cron route is chosen: `privacy-auditor` runs (new route outside `/private`). N/A — hook-based, no new route.
- [x] `pnpm typecheck`, lint on changed files and unit tests pass (exit codes in handoff)
