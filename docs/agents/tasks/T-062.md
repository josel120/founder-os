# T-062: One-command production setup for Vercel and Neon

- Status: review
- Owner: claude
- Size: M
- Depends on: T-052, T-053, T-055

## Goal
The owner found the manual Vercel + Neon setup (T-056) too hard. One command on the owner's machine, `pnpm setup:production`, does it: Vercel login and link, a Neon database through the Vercel Marketplace (production only), env vars with a locally generated secret, migrations, the owner account, a production deploy and a smoke check. No secret is ever printed, put in a command line, or seen by an agent.

## Acceptance criteria
- [x] On Vercel, `BETTER_AUTH_URL` defaults to the deployment's own https origin from Vercel system variables (production: `VERCEL_PROJECT_PRODUCTION_URL`; preview: `VERCEL_BRANCH_URL` or `VERCEL_URL`). An explicit `BETTER_AUTH_URL` still wins. Better Auth trusts only this deployment's own Vercel origins. The client uses the page origin when `NEXT_PUBLIC_BETTER_AUTH_URL` is unset. Unit tests cover all of this.
- [x] `scripts/setup-production.ts` (`pnpm setup:production`, cross-platform Node via tsx, no new dependency; Vercel CLI via a pinned `npx vercel@60.1.3`). Steps, each skippable when already done: login, link, `vercel integration add neon` for production only, env vars (`ENABLE_EXPERIMENTAL_COREPACK`, `OWNER_EMAIL`, `BETTER_AUTH_SECRET` via stdin, `--sensitive` where secret), migrations on the unpooled URL from a temporary env pull (deleted afterwards, never `.env.local`), owner creation in-process through Better Auth's own sign-up with an ephemeral setup token, `vercel deploy --prod` from a clean, up-to-date `master`, and the RUNBOOK section 10 smoke check. `--dry-run` prints the plan without secrets.
- [x] `.vercel` is gitignored; RUNBOOK sections 1–5 lead with the one-command path, with the manual steps kept as fallback.
- [x] `pnpm typecheck`, lint, unit tests and `pnpm build` pass (exit codes in handoff)
