# T-063: Let the owner reset a forgotten email or password with the setup command

- Status: done
- Owner: claude
- Size: S
- Depends on: T-062

## Goal
After deploying, the owner could not sign in: they no longer knew the email or password given to `pnpm setup:production`. A re-run skipped the existing owner, and a re-run with a new email silently broke sign-in, because `OWNER_EMAIL` changed while the account kept its old email. `pnpm setup:production --reset-owner` gives the one existing account the new email and password, and signs out its old sessions.

## Acceptance criteria
- [x] `--reset-owner` updates the existing owner through Better Auth's own adapter and hashing (`updateUser`, `password.hash`, `updatePassword`, `deleteUserSessions`), then deploys, so the new `OWNER_EMAIL` takes effect.
- [x] Without `--reset-owner`, an owner under a different email stops the run with the exact command to fix it. It never leaves an unmatched `OWNER_EMAIL` unexplained.
- [x] More than one account in the database fails closed (`MORE_THAN_ONE_ACCOUNT`) instead of guessing.
- [x] Unit tests for every outcome; proven against a real Postgres (create → mismatch exit 5 → reset exit 4 → new credentials sign in, old password and old email rejected).
- [x] `pnpm typecheck`, lint, unit tests and build pass.
